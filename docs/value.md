# Value: вид значення поряд із бітами

Value — невеликий навчальний тегований запис для значень різного призначення.
Його поля: Kind kind і uint16_t bits. Kind може бути Byte, Addr або SpriteId.
Це не новий регістр ISA і не новий формат байткоду; це приклад моделювання даних на хості.

~~~cpp
Value address{Value::Kind::Addr, 0xC00};
Value byte{Value::Kind::Byte, 65};
Value sprite{Value::Kind::SpriteId, 2};
~~~

В усіх трьох випадках bits має той самий тип. Саме kind каже, як його читати.
Адреса0xC00 і байт0x00 не повинні випадково стати одним поняттям через обрізання до8 бітів.
Перевірений приклад у tests/layout.cpp створює Addr0xC00 та звіряє і тег, і3072.

| Зміщення в цій збірці | Зміст | Розмір |
|---|---|---:|
|0|Kind з uint8_t|1|
|1|padding|1|
|2|bits uint16_t|2|

Отже sizeof(Value)=4, align=2. Ці значення виміряні, не вгадані.
Тег займає пам'ять, але дає можливість перевірити вид під час виконання.
Значення полів відкриті: сам struct не забороняє створити Byte із bits=300.
Код, який приймає Value, має перевіряти і тег, і межі: Byte<=255, Addr<4096,
SpriteId<8. Поточний проєкт використовує Value для демонстрації запису й розкладки,
а не як універсальну систему всіх гостьових значень.

## Чим відрізняється union

Union накладає кілька членів на одну ділянку. Його розмір достатній для найбільшого члена
з урахуванням вирівнювання; одночасно активний лише один член.
Після запису одного виду не можна просто припускати, що читання довільного іншого виду
є визначеним способом перетлумачення. Для копіювання представлення float у uint32_t
наш дослід використовує memcpy, а не таке читання union.

Голий union не містить автоматичної відповіді «який член активний».
Програміст мусить зберігати її окремо. Тегований запис робить цю відповідь частиною даних.
Повноцінний tagged union зберігав би enum та union і підтримував би відповідність між ними.
У нашому простішому Value всі варіанти вкладаються в uint16_t, тому union усередині взагалі не потрібен.

## Ціна та межі

Більша гнучкість потребує перевірок. Перелік Kind допомагає компілятору розрізняти назви,
але явний cast із довільного числа все одно може створити невідомий тег.
У розборі таких даних потрібен default із відмовою. Зміна bits без зміни kind теж може
порушити домовленість. Тег — інформація для перевірки, а не автоматичний доказ правильності.

Такий приклад достатній для Advanced Lab06 разом із ALLOC та справжнім звітом LSan.
Альтернативний FREE зі списком вільних блоків мав би іншу мету: відстежувати розміри й повторне
використання гостьових ділянок. Його не додаємо лише заради кількості можливостей:
обраний bump-алокатор має просту й точну поведінку, а Value показує окрему ідею — явний вид даних.
